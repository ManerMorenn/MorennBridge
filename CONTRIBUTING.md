# Contributing

Bug reports and pull requests are welcome. For anything large, open an issue first so we can agree on the approach.

## Setup

You need Blender 4.5 or newer. The test runner links the checkout into your user extensions folder and enables it.
There is nothing else to install to run the tests.

```
blender -b --factory-startup --python tests/run_tests.py -- [-k pattern] [-v]
blender --factory-startup --python tests/gui_session.py
pip install ruff==0.17.3 && ruff check . && ruff format --check .
```

The second command opens a window for a few seconds: it draws every panel and checks undo. Fixtures are procedural
(`tests/fixtures.py`), so no .blend files go into the repository.

Add a test with every bug fix. New issue codes need an entry in `docs/ISSUES.md`, which a test enforces.

To measure coverage, install `coverage` into a separate folder for Blender's Python version and point
`MORENN_COVERAGE_LIB` at it. CI fails below the threshold in `pyproject.toml`.

## Documentation

Pages live in `docs/`. The website is built from them with `python dev/build_site.py --out site`, which needs
`pip install markdown pymdown-extensions pygments`. Screenshots are regenerated by `dev/make_screenshots.py`, except
`docs/images/11_…` and up: those are manual captures of Unreal Engine 5.8.4 and of the Unreal Link panel with an
editor found, cropped to the relevant part.

## Style

Code is formatted by `ruff format`, with 120 columns. Keep comments short and factual. The add-on must not write into
its own folder, change other add-ons, or use the network unless `bpy.app.online_access` is on.

Blender API differences between versions belong in `compat.py`. Code that runs inside Unreal lives in `ue/scripts`,
and anything touching the `unreal` module needs a check in a live editor before it counts as done. The tests run
these scripts against `tests/fake_unreal.py`. Every Unreal name they use, and every name the fake declares, must exist
in the editor's Python stub: with *Developer Mode* on (Editor Preferences → Plugins → Python), the editor writes it
to `<Project>/Intermediate/PythonStub/unreal.py`, and `python dev/check_ue_names.py <stub>` compares.

`python dev/ue_smoke/run.py --blender <blender> --editor <UnrealEditor-Cmd> --project <test.uproject> [--roundtrip]`
exports test scenes with the add-on, imports them into a test project with `ue/scripts` (no editor window) and
checks names, LODs, collision, sockets, shading, skeletons, animations and vertex colours with Unreal's Python.
`--roundtrip` also sends the Third Person template's mannequin through Blender and back, and the UE4 mannequin when
the project has it (copy the engine's `Templates/TemplateResources/Standard/Mannequin/Content` to
`<Project>/Content/Mannequin`). Use a project made for
testing: the run replaces `/Game/MorennBridgeSmoke`. With the project open in the editor and remote execution on,
`--remote` (no `--editor`) checks Unreal Link instead: discovery, push, pull and push back, through paths with
spaces and accents. `--real <dir>` round-trips every FBX file of a folder (characters made elsewhere) and compares
the result with Unreal's own import of the original; keep such files outside the repository.

`python dev/check_fbx_sdk.py <file or folder> [...]` opens FBX files with the Autodesk FBX SDK and flags files it
cannot import, LOD levels without a mesh, clusters without a bone and skinned meshes without a bind pose. The SDK has
its own licence and is not part of this repository: install its Python wheel (Python 3.11 for 2020.3.11) yourself.

## Versions

The version follows [semantic versioning](https://semver.org) and lives in `__init__.py` and `blender_manifest.toml`,
which a test keeps equal. Update `CHANGELOG.md` with every release.

These count as public formats:

- **Stored properties** on objects, armatures, bones and scenes: new properties need defaults, and a rename or removal
  needs a conversion when the file is loaded.
- **Preferences**: same rule.
- **The manifest**: new keys are fine, anything that breaks readers raises `version`.
- **FBX markers** such as `MorennBridge|BoneAxes`: importers must keep reading old values.

## Releases

1. Update the version in both files and date the changelog entry.
2. Push to `main` and wait for CI.
3. Tag `vX.Y.Z`. The release workflow runs CI again, then publishes the zip and its checksums.
4. Upload the same zip to extensions.blender.org.
